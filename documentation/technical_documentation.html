2. Document and synchronisation

All modifications go through MotorDocument.modify(text, kind, mutate):

  1. a deep copy of the motor is taken (before);
  2. mutate(motor) applies the change; if nothing changed nothing is recorded;
  3. a SnapshotCommand (before/after) is pushed on the QUndoStack;
  4. the cached analysis is invalidated and changed(kind) is emitted (points, metadata, plot, label or all).

The table model, the graph, the properties form, the label designer and the status bar listen to changed. The graph and the table never modify each other directly: they both emit requests to the document, which guarantees perfect synchronisation and undo support for every operation.

3. Calculations (models/motor_calculations.py)

QuantityFormula
Total impulse I∫F dt by the trapezoidal rule on the samples, with the implicit origin (0, 0) prepended when the first sample is later than 0.
Burn time (curve)From the last zero-thrust sample before ignition to the first zero-thrust sample after burnout.
Burn time (threshold)Between the linearly interpolated crossings of 5 % of the maximum thrust (NAR/NFPA 1125 convention).
Average thrustI / burn time.
Specific impulseI / (mprop[kg] · g0), g0 = 9.80665 m/s².
Impulse classA = 1.26–2.50 N·s, each letter doubles; 1/2A, 1/4A, 1/8A below.

Each result is None when it cannot be computed, with the reason in MotorCharacteristics.unavailable.

4. ENG format (services/eng_service.py)

; comments
C6 18 70 0-3-5-7 0.0108 0.0231 Estes
   0.031 0.946
   ...
   1.86 0

Reader: several motors per file, inline and trailing comments preserved, precise FileFormatError with line number and content. Writer: validation first (errors block, warnings need confirmation), whitespace-free ASCII tokens, plain decimal numbers (max. 6 decimals), implicit (0, 0) omitted, CRLF, atomic write. No non-standard information is added; it lives in the XML project.

5. Project format (services/xml_service.py)

<RocketMotorProject formatVersion="1.1" application="Rocket Motor Manager" applicationVersion="1.0.0">
  <Metadata>Created, Modified, SourceFile, Extra/Item@key</Metadata>
  <Motor>
    <General>Name, Manufacturer, Designation, Delays, PropellantType, Description, Comments</General>
    <Dimensions unit="mm">Diameter, Length</Dimensions>
    <Masses unit="g">Propellant, Casing, NozzleClosure, DeclaredTotal, Total@computed</Masses>
    <EngComments>Line*</EngComments>
    <ThrustCurve timeUnit="s" thrustUnit="N" count="n">Point@t@f*</ThrustCurve>
  </Motor>
  <CalculatedCharacteristics burnTimeMethod="curve" informative="true">Value@key@unit*</CalculatedCharacteristics>
  <PlotSettings show_grid=".." line_color=".." .../>
  <Label width_mm=".." ...>Field@name*</Label>
</RocketMotorProject>

Floats are written with repr() (exact round trip). To evolve the format: increase CURRENT_FORMAT_VERSION, write a migration function and register it in MIGRATIONS. Files with a newer major version are refused; a newer minor version loads with a warning.

6. Digitizer pipeline (services/image_digitizer.py)

  1. load_image (unicode paths, 16-bit, alpha flattened);
  2. geometric corrections (perspective, rotation, crop) applied to a working image, photometric corrections (contrast, brightness, grey, denoise) applied live in a background thread;
  3. AxisCalibration: affine least-squares fit [t, F] = M · [x, y, 1] over ≥ 3 non-collinear references, RMS residual in pixels;
  4. colour mask in CIE-Lab with tolerance, speck removal (connected components), one pixel per column inside the plot area;
  5. robust outlier rejection (rolling median + MAD), conversion to physical units, strictly increasing times, optional resampling / Douglas-Peucker simplification, closing zero point.

6b. SRM workbooks (services/srm_service.py)

Richard Nakka SRM workbooks are read with ExcelService.read_grids() (xlrd for .xls, openpyxl for .xlsx). Values are located by their labels (case-sensitive, spaces and trailing colon ignored: Do ≠ do), never by fixed cell addresses, so SRM 1.x (numeric propellant code) and SRM 2023 (propellant name, Nozzle Design sheet) are handled by the same code. The Performance curve (columns t and F in N) integrates exactly to the workbook's total impulse; the Output 23-point table is offered as an alternative. A deviation above 2 % between the curve and the workbook result is reported.

7. Labels (services/label_service.py)

A single LabelRenderer draws in millimetre coordinates on any QPaintDevice (screen preview, QPrinter, QPdfWriter, QImage), so all outputs are identical. Font sizes are converted with the device DPI so a 10 pt font is 3.53 mm high everywhere. Sheet layouts are computed from the paper format, margins and spacing; images embed their DPI.

8. Reliability

  • Exception hierarchy: RocketMotorError → FileFormatError, FileAccessError, ValidationError, CalibrationError.
  • install_exception_hook() catches every uncaught exception (main and worker threads), logs it and shows a dialog.
  • Rotating log (1 MB × 5) in %LOCALAPPDATA%\RocketMotorManager\logs.
  • Atomic saves (temporary file + os.replace); confirmation before overwrite and before losing unsaved changes.
  • Damaged preferences fall back to defaults.
  • Resources are located by application.paths.resource_path(), file by file: beside the executable (external resources / documentation folders), then in the PyInstaller bundle (sys._MEIPASS), then in the source tree. The same code supports the one-folder build, a --onefile build with embedded resources and a --onefile build with external resources (build_onefile_external.bat); tools/check_bundle.py verifies any of them.

8b. Internationalisation (localization)

The application texts use GNU gettext through the Qt-free localization package, so the business layer (validation messages, calculation reasons, file errors) is translated as well as the interface. Strings are marked with _(), ngettext() (plural forms: 2 in most languages, 3 in Polish and Russian) and N_() for constants translated at display time. Placeholders are named str.format fields so translators may reorder them. The language is installed once at start-up, before the user interface is built (a change in the preferences takes effect after a restart).

FileRole
resources/locale/rocketmotormanager.potTemplate extracted from the sources by Babel
resources/locale/<lang>/LC_MESSAGES/rocketmotormanager.poTranslations (fr, de, es, it, nl, pl, pt, ru)
resources/locale/<lang>/LC_MESSAGES/rocketmotormanager.moCompiled catalogue loaded by gettext

tools/build_translations.py extracts, merges (changed messages become fuzzy), checks (untranslated, fuzzy, placeholder mismatch) and compiles. Data written to files (ENG, XML, CSV headers) is never translated. Qt's standard dialogs use Qt's own qtbase_<lang>.qm catalogues via QTranslator.

User manual. The manual texts form a second gettext domain, manual (documentation/locale/<lang>/LC_MESSAGES/manual.po), extracted from tools/generate_manual.py. Interface references are written [[&File|&New Motor]] and replaced at generation time by the captions of the application catalogue (mnemonic and ellipsis removed), so the manual always uses the words of the translated interface; build_translations.py and the tests check that every reference exists and is kept by the translators. generate_manual.py produces documentation/user_manual_<lang>.pdf with the DejaVu Sans fonts (Latin, Polish, Cyrillic) and the screenshots of documentation/screenshots/<lang>/. MainWindow.open_manual() opens the manual of localization.current_language(), or the English one when it is missing.

9. Tests

python -m pytest runs 180 tests: ENG read/write/round-trip and invalid files, CSV detection/import/export, Excel .xlsx/.xls, XML save/load/migrations/corruption, calculations against analytical curves, units, validation, digitizer accuracy on synthetic graphs (median error < 0.1 N, impulse within 2 %), labels, preferences and offscreen UI smoke tests (table ↔ graph synchronisation, undo/redo, windows), translation catalogues (completeness, placeholders, plural forms, up-to-date with the sources) the main window in every language, the manual catalogues (complete, interface references valid), the PDF manuals and the choice of the manual by Help > Manual.

10. Adding a feature

  • New file format: add a service returning a Motor or TabularData, then an action in MainWindow.
  • New characteristic: compute it in MotorCalculator, add a row in MotorCharacteristics.as_rows() and its quantity in services/thrust_analysis.py.
  • New label field: add it to LABEL_FIELDS/LABEL_FIELD_CAPTIONS and to label_values().
  • New language: python tools/build_translations.py init xx, translate both .po files (application and manual), add the code to localization.LANGUAGES, run python tools/build_translations.py.
